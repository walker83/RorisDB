# HarnessDB Bug 修复计划

## 调查结论

我已经用 4 个并行 agent 逐条核验了 BUG_REPORT.md 中标注"已修复"的 ~46 个 bug，并实测复现了 481 个 e2e 测试失败的根因。核心发现：

- **大部分"已修复"的 bug 确实已修复**（约 40 个为真修复）
- **481 个 e2e 测试失败是单一根因**：`fe_main.rs:440` 用 `secure_credentials()`（随机 root 密码），测试用 root 无密码连接
- **明确仍坏的真实 bug 约 15 个**（不含 Oracle/TDS 骨架重写）

## 修复内容（按优先级分组）

### 🔴 P0：修复 481 个 e2e 测试失败（认证根因）
1. **harness-server/src/fe_main.rs** + clap `Args`：新增 `--dev` 布尔标志；当 `--dev` 为真时，第 440 行改用 `default_credentials()`（root 空密码），否则保持 `secure_credentials()`
2. **抽取共享测试 harness**：把 14 个 e2e suite 文件里重复的 `E2eServer`/`find_binary`/`make_conn`/`Drop` 抽到 `tests/integration/src/common.rs`（或新建 `harness.rs`），共享 spawn 逻辑统一传 `--dev` 参数；14 个 suite 文件改为 `use integration_tests::common::...`
   - 预期：481 → 接近 0 失败（剩余失败才反映真实功能性 bug）

### 🔴 P1：CRITICAL 协议正确性 bug
3. **PG 参数化查询（$1/$2 不工作）** — `crates/pg-protocol/src/connection.rs`
   - 扩展 `PreparedStatement` 增加 portal 级参数存储；`SessionState.portals` 改为存 `(stmt_name, Vec<param_values>)`
   - `handle_bind`：接收 Bind 消息的 `values`/`formats`，按 text/binary 格式解码为字符串，存入 portal
   - `handle_execute`：取出 portal 参数，在调用 handler 前对 SQL 做 `$1`/`$2`/... 字面量替换（复用一个新增的 `substitute_params` 工具函数，正确处理引号内的占位符、字符串字面量转义）
4. **PG Execute 错误路径双重 ReadyForQuery** — 同文件
   - 移除 `handle_execute` 各错误分支里的 `send_ready_for_query()`；ReadyForQuery 只在客户端发 Sync 后发（符合 PG 扩展查询协议）。保留 Sync 分支（329 行）的发送
5. **Cassandra ROWS 结果缺 Metadata 段** — `crates/cassandra-protocol/src/handler.rs` `build_rows_result`
   - 在 column count 后插入 CQL v4 Metadata：flags(int)、global table spec、每列 `[string name][u16 type]`

### 🟡 P2：HIGH 功能性 bug
6. **ADB MySQL 聚合函数 SUM/AVG/MIN/MAX 返回 "0"** — `crates/adb-mysql-protocol/src/handler.rs`
   - 扩展 `AggFunc` 枚举增加 `Sum/Avg/Min/Max(usize col_idx)`
   - select 列解析（394-411 行）：识别 SUM/AVG/MIN/MAX 及 COUNT(col)，记录目标列索引，而非返回 `Literal("0")`
   - 聚合执行（238/256/511 行）：实现真实聚合计算；NaN 处理（修正 handler.rs:824 NaN 比较）
7. **DML affected_rows 在 tsql-executor 被丢弃** — `crates/tsql-executor/src/query_handler.rs:61-63`
   - `Ok(TsqlExecutionResult::RowsAffected(n))` 分支改为 `QueryResult::ok_with_affected(n)`（或等价），把 n 传给协议层
8. **ES bulk update 对不存在文档仍返回 200** — `crates/elasticsearch-protocol/src/handler.rs:337-364`
   - 当 `index.get_document(&id)` 为 None 时，push 的 item 状态改为 404 / result "not_found"
9. **ES POST `/{index}/_doc/{id}` 始终返回 created** — `handler.rs:418-443`
   - 像 PUT 路径一样检查 `existed`，返回 updated/created
10. **安全凭证硬编码（MaxCompute + PG）** — `fe_main.rs:481-514`
    - MaxCompute：env 未设置时不回退到 "harness"/"harness-secret"，改为生成随机值并警告（与 `secure_credentials` 模式一致）
    - Hologres/PG：`PgServerConfig` 的 username/password 改为从 env 读取，未设置时随机生成

### 🟢 P3：MEDIUM 协议合规性 bug
11. **PG information_schema 路由用 contains** — `crates/pg-protocol/src/catalog.rs:253-267`：改为 `starts_with` / 精确匹配
12. **InfluxDB 行协议转义** — `crates/influxdb-protocol/src/line_protocol.rs`：`parse_measurement_tags`/`parse_fields_timestamp`/`parse_field_value` 处理 `\,` `\ ` `\=` 转义；布尔补全 `TRUE`/`FALSE`
13. **SQL parser `parse_set_value` 转义替换顺序** — `crates/fe-sql-parser/src/parser.rs:949-952`：先替换 `\\` 再替换 `\'`/`\"`
14. **SQL parser `DROP ANALYZE JOB` 大小写** — `parser.rs:324-336`：用 `strip_prefix_ci` 替代 `strip_prefix`
15. **Redis 递归解析无深度限制** — `crates/redis-protocol/src/resp.rs` `measure_value`：加深度计数器，超限（如 128）返回错误
16. **ClickHouse INSERT 静默丢弃多余列** — `crates/clickhouse-protocol/src/storage.rs:29-41`：`values.len() > column_order.len()` 时报错而非静默截断
17. **PG Describe 对行返回查询仍执行副作用**（部分修复的残留）— 评估后若影响正确性则改为用缓存字段而非重新执行

## 执行方式
- 每个修复点附 1-2 个单元/回归测试（利用各 crate 现有 `#[cfg(test)] mod tests` 模式）
- 每组修复后跑 `cargo build --workspace` + 相关 crate `cargo test -p <crate>`
- 全部完成后跑 `cargo test --workspace`，目标是 481 失败 → 接近 0，其余测试不回归
- 提交粒度：按 P0/P1/P2/P3 分组提交，每个 commit 信息描述修复的 bug

## 不做
- 不重写 Oracle/TDS/Sybase/TSQL 骨架（95 个 bug，需完整协议实现）
- 不做大规模性能优化（全表内存模型等）
- 不做文档覆盖率提升
- 不动 `unsafe transmute`（fe-storage/lib.rs:124，有 Drop 顺序不变量保护，改它风险高于收益）
